# Full kernel regression queue

Run on anonymous@192.168.2.183 in /data/src/openwrt:

```sh
bash scripts/act-kernel.sh --plan
bash scripts/act-kernel.sh --all
bash scripts/act-kernel.sh --status
bash scripts/act-kernel.sh 'bcm27xx/bcm2709@6.12' 'malta/be@6.18'
bash scripts/act-kernel.sh 64 legacy
bash scripts/act-kernel.sh --resume <batch-id>
```

The default is the entire supported matrix, generated by the same
scripts/dump-target-info.pl kernels metadata used by GitHub kernel CI.
Each target/subtarget is tested on its default and testing kernel; equal
versions are deduplicated. Targets marked broken or source-only are
excluded by upstream metadata. The current source declares 97 buildable
subtargets and 110 distinct combinations across 6.12, 6.18 and 7.2.
--plan recalculates this list; counts are not hardcoded.

Each batch freezes the source commit and tracked local diff. The job
checks the selected kernel branch and compiled kernel.release against
the matrix. Testing kernels enable CONFIG_TESTING_KERNEL before the
first defconfig. ALL_KMODS=y and KERNEL_WERROR=y apply to every job.

Docker uses /data/act/docker. Each job uses its matching official
ghcr.io/openwrt/toolchain:<target>-<subtarget>-latest image, recorded by
digest. Build workspaces are independent under /data/act/runs. Only
downloads are shared with the production tree; its .config is never
mounted into builds. A final checksum check records configuration safety.

ACT_KERNEL_PARALLEL is 2 by default (supported: 1 or 2). Each container
defaults to ACT_KERNEL_JOBS=32 CPUs and ACT_KERNEL_MEMORY=40g. An exclusive
queue lock prevents competing batches from oversubscribing the host.

Stages: external toolchain setup, defconfig/version assertions,
tools/install, toolchain/install, target/linux/clean, target/compile and
package/linux/compile -k. Keep-going packaging collects all failures but
still returns nonzero. Missing images and setup errors are failures, not
skipped or passed combinations. A failed job does not stop other jobs.

Records are /var/log/agw-act/<batch-id>/<combination-key>: image digest,
source SHA/diff, frozen workflow, phase logs and exit codes, final config,
kernel config/release, selected kmod list, APK inventory and kmods.tar.
Batch summary.tsv and per-job state files distinguish PENDING, RUNNING,
PASS and FAIL_<phase>. Stopping the queue marks cancellation separately.
--status reads live per-job states. --resume continues pending/interrupted
jobs in the frozen batch and does not retest completed PASS/FAIL entries.
To retry a failed combination after a source fix, start a new targeted batch.

Successful workspaces and containers are removed after artifact archival.
Only the two most recent failed workspaces are retained; all failure logs
and diagnostics remain. Images and downloads are cached. Below 50 GiB
free space, the scheduler waits for active jobs to reclaim space; if that
is insufficient it stops with STOPPED_DISK rather than silently skipping
combinations. Free space and use --resume to continue.

The systemd service agw-kernel-regression runs --all independently of SSH.
Inspect with systemctl status agw-kernel-regression and --status above.
The service is not automatically restarted on build failure. After a
machine restart, an interrupted batch can be resumed explicitly.

This checks all declared target/kernel combinations, not every device
profile, firmware image or runtime boot. Other architectures are cross
compiled in native amd64 containers. No GitHub secrets are required.
